# Изменения

> Русский · [English](CHANGELOG.md)

Здесь описана текущая линия разработки и то, на что стоит посмотреть при обновлении.
Версии, которые можно скачать, и даты их публикации — в
[GitHub Releases](https://github.com/ParkPavel/obs-projects-plus/releases).
Версия в [manifest.json](manifest.json) обозначает это дерево исходников и не означает,
что выпуск опубликован.

## Не выпущено

### Документация

- Документация для пользователя переписана короче. README — 62 строки вместо 305, руководство —
  168 вместо 688: каждая страница отвечает на вопрос читателя, а не перечисляет всё, что есть
  в плагине.
- Документация для разработчика переписана тоже. Одна карта кода связывает каждую ответственность
  с файлом, который её реализует; одно руководство для контрибьюторов несёт правила кода —
  поэтому две страницы `CODE_STANDARDS` удалены, и ни одно правило с ними не пропало.
  Справочники API и заметки в `src/lib` переписаны по текущему исходному коду.
- Исправлено то, что больше не совпадало с плагином: у проекта четыре представления — Dashboard,
  Доска, Календарь и Галерея, — таблица не отдельное представление, а блок внутри Dashboard,
  и единственная публичная точка расширения — `onRegisterProjectView`. Описанного в руководствах
  API `getProjects` / `createProject` / `registerView` не существует.
- У каждого документа есть русская и английская версия: парой файлов или двумя языками в одном
  файле — для указателя, кодов ошибок и двух страниц, которые читатель встречает внутри
  хранилища. Парность проверяется тестом.
- Внутренние планы, отчёты агентов, инструкции для сессий и дублирующие документы о выпусках
  больше не входят в дерево. Разработка ведётся через
  [Claudex](https://github.com/ParkPavel/claudex), прежние версии остались в истории Git.

### Исправления

- Строка в консоли больше не цитирует шаблон сообщения. У кодов, в тексте которых есть подстановка
  вроде `{{path}}`, она печаталась как есть: пользователь, копируя консоль в отчёт, присылал шаблон,
  тогда как уведомление рядом называло настоящий файл. Подстановка, которую нечем заполнить, теперь
  выглядит как `<path>` — это говорит читателю, что значение неизвестно, а не что код недоделан.

### Разработка

- Отставлены тесты старых внутрипроектных агентских хуков и конфигурации. Тесты поведения
  плагина остаются здесь; Claudex проверяет свою обвязку и ограждения публикации сам.
- Тест порядка фильтрации больше не проверяет фразы в документе, а закрепляет разводку кода —
  то, что может сломаться молча.
- CI проверяет pull request, не записывая бета-метаданные и не пушив изменения в `main`.
  Выпуски по тегу по-прежнему идут через отдельный процесс.

## 3.6.0-alpha

Это версия в разработке. Ниже — изменения, которые влияют на заметки, сохранённые
представления или на то, как вы работаете с плагином.

### Связи и данные Dashboard

- Поле-связь определяет заметку по ссылке и сообщает, если ссылка не нашлась или совпала
  неоднозначно. В мастере настройки можно выбрать целевой проект и отображаемое поле.
- Связанные записи и подсчёты по ним могут брать данные из другого проекта. Действия на
  Dashboard умеют сужать записи блока через существующую связь.
- Блок с внешним источником берёт из него и данные, и настройку полей. Галерея с внешним
  источником работает только для чтения.

### Что учесть при обновлении сохранённых Dashboard

- Фильтр блока сужает записи **до** расширенных преобразований. Сохранённый Dashboard, где
  используется и то и другое, после обновления может показать другой результат.
- При переносе ведущий фильтр конвейера переезжает в фильтр блока только тогда, когда это
  безопасно. Условия, которые зависят от столбца, созданного конвейером, остаются на месте.
  Меняется настройка представления, а не сами заметки.
- Старый виджет sub-base больше недоступен. Прежние поля настройки остаются читаемыми для
  совместимости, но удалённый виджет не возвращают.

### Исправления

- Настройка подсчёта по связанным записям, сделанная в интерфейсе, доходит до движка расчёта.
- Мастер настройки связи дожидается результата записи и сохраняет выбранное отображаемое поле.
- Обновление записи сообщает о неудачной записи вместо того, чтобы считать её выполненной.
- Сгенерированные демонстрационные Dashboard используют текущее представление фильтра блока.
- Сборка стилей проверяет наличие рукописных стилей до того, как собрать устанавливаемый бандл.
