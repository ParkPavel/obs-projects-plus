| Миграция + 3 файла восстановления | миграция сработала, payload — до-состояние (сверены `projectId`/`viewId` и отсутствие `subFilter`) | что из файла можно восстановиться; что при отказе адаптера пользователь это заметит |

## Что нельзя проверить ни API, ни глазами без специальной подготовки

- **Отказ записи.** Нужен файл, недоступный для записи (атрибут «только чтение» или занятость
  другим процессом). Без этого ветки компенсации #144/#161/#163 не наблюдаемы вживую.
- **Гонка отложенной записи** (#145, замечание аудита): бэкап пишется fire-and-forget, и если
  Obsidian закрыть в ту же миллисекунду, файла может не быть. Воспроизводится только жёстким
  закрытием сразу после открытия дашборда.
- **Восстановление из бэкапа.** Файл существует и содержит верное до-состояние — но процедуры
  «вернуть конфиг из файла» в продукте нет, значит проверять нечего. Это открытый вопрос, а не
  проверка: см. #145.
- **Консольные ошибки при рендере.** REST возвращает 204 на `POST /commands/...` даже если вью
  упало при отрисовке. Только глазами, с открытым DevTools.
