# CX-MAP-191 — карта «шаблонов»

Роль: `code-mapper`, база `HEAD~1`, 2026-09-04. Запрошено после замечания пользователя, что
шаблоны — устаревший артефакт.

## Главное: под одним словом два несвязанных механизма

**1. Шаблоны записи — живой путь целиком.**
`ProjectDefinition.templates` (пути к `.md`) → селектор в `CreateNote.svelte:30,154` →
`ViewApi.addRecord` передаёт `templatePath` (`viewApi.ts:63`) → `DataApi.createNote` читает файл,
подставляет `title`/`date`/`time` (`dataApi.ts:145`) и создаёт заметку, затем пишет поля
(`dataApi.ts:180`). У каждого звена есть потребитель и наблюдаемый эффект.

**2. Шаблоны дашборда — тоже живые.**
Раскладки виджетов в коде (`widgetTemplates.ts:38`) → пустой холст и панель инструментов
(`WidgetGrid.svelte:70`, `WidgetToolbar.svelte:26`) → `DashboardCanvas.svelte:134` →
`dashboardTemplates.ts:41` пишет `widgets` в `DatabaseViewConfig`. Дополнительно достижимы через
сохранённое быстрое действие `kind: "apply-template"`, которое резолвится по `templateId`
(`dashboardTemplates.ts:80`).

**3. «Шаблоны» демо-проекта — вообще не они.** В `demoProject.ts:72` это локальные генераторы тела
заметки, не потребители `ProjectDefinition.templates`. Совпадение слова.

## Мёртвое

`getVerticalTemplates` (`widgetTemplates.ts:559`) — ноль статических вызовов и импортов.
Единственный кандидат на удаление по образцу #178/#183: карта + сравнение бандла до/после.

Файла с нулём импортов не нашлось: `interpolate.ts` импортируется из `dataApi.ts:20`,
`createNoteModal.ts:8` и `CreateProject.svelte:29`.

## Что сломается при удалении — по частям

- убрать настройку шаблонов проекта: сохранённые пути останутся читаемыми, но менять их будет негде;
- убрать селектор при создании записи: пропадёт выбор и сброс шаблона, новые записи пойдут по
  начальному значению «первый шаблон» (`CreateNote.svelte:30`);
- убрать поверхности шаблонов дашборда: исчезнет разметка холста в один клик, при том что контроллер
  и определения остаются вызываемыми из быстрых действий.

## UNKNOWN — и это ограничивает решение

Какие `templateId` реально лежат в хранилищах пользователей, статический разбор перечислить не может:
быстрые действия хранят идентификатор строкой (`dashboardTemplates.ts:85`). Удаление шаблонов
дашборда без проверки настоящих хранилищ сломает чью-то сохранённую кнопку молча.

Существуют ли настроенные пути шаблонов в конкретном хранилище, тоже не выводится: отсутствующий
путь проваливается в пустое начальное содержимое (`dataApi.ts:152`).

## Вывод для тикета #191

«Устарело» — вопрос продукта, а не кода: оба механизма работают и имеют эффект. Технически удалять
сейчас можно ровно одну мёртвую функцию.
