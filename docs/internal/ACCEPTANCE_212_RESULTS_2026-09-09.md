## 3. Дефект, который нашёл прогон

**Наблюдение.** Внешняя версия, записанная в момент, когда собственная запись плагина стояла в
дебаунсе, **затиралась молча**: ни конфликтной копии, ни уведомления, ни следа. Воспроизведено
трижды при задержках 300/400/500 мс, затем контрольным опытом с меткой:

```
external version written at +350ms, marker: ТОЛЬКО-СНАРУЖИ-91006
after: Гонка-063047-4400, Демо-проект
marker survived in data.json: false
conflict copies: 0; recovery notes: 0
LOST — no copy, not in the file
```

**Причина.** Асимметрия, стоявшая с #199: файл перечитывался **после** записи и никогда до неё.
Пост-проверка доказывает, что наши байты легли, и ничего не говорит о том, на что они легли. Наша
отложенная запись выигрывала гонку у события хоста, и о чужой версии не узнавал никто.

**Правка (`7c1d262`).** Перед записью писатель спрашивает: файл всё ещё тот, который сеанс подтверждал
последним? Если нет — значение не пишется, случай становится расхождением, поднимается ограждение,
решение уходит реконсиляции. Неизвестность («базы нет», «файл не читается») отвечает «пиши»: отказ от
всех записей — это отвергнутая `PLAN_200` §2 модель, где не сохраняется ничего.

**И вторая правка, тоже с прогона (`cf0044b`).** Первый же прогон с новым стражем дал **237
конфликтных копий**: восстановление, завершающее эпизод, — само запись, и страж отвергал его, сравнивая
файл с базой, снятой до эпизода. Эпизод теперь запоминает то, что увидел, и позади стоит второй
предел: из отказанных записей ставится в очередь не более одной реконсиляции.

## 3a. Повтор после правок ревью (тот же день, `5e06489`)

Гейт после первого прогона нашёл ещё три вещи, две из них меняли поведение записи: `rejected` вместо
`diverged` при отказе перед записью (правка возвращает значение в очередь — иначе правка пользователя
исчезала молча при статусе «сохранено») и запись базы при исходе «делать нечего» (иначе проверка
отвергала запись бесконечно, каждый дебаунс). Поэтому прогон повторён целиком на сборке с ними.

**Снова 8 из 8**, включая `BIND` (дерево чистое, md5 совпадают, Obsidian перезапущен после
развёртывания). Плюс повторён опыт с меткой: чужая версия не в `data.json`, но **ровно в одной**
конфликтной копии — и через двадцать секунд покоя копий по-прежнему одна, то есть найденной ревью
живой блокировки на стенде нет.
