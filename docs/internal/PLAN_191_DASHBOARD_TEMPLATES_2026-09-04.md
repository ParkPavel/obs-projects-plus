# План #191 — «Шаблоны дашборда: удалить механизм, не оставив кнопку без эффекта»

**Ветка:** `feat/191-drop-dashboard-templates` | **База:** `main = ddc7200` | **Проход:** архитектурный, read-only.

> Записано `lead`-ом с финального сообщения архитектора (у роли нет `Write`). **Числа проверены**
> перед записью: `DashboardCanvas` 200, `WidgetGrid` 178, `WidgetToolbar` 178, `widgetTemplates` 577,
> `dashboardTemplates` 99, `TemplateConfirmDialog` 92 — все шесть совпали, впервые за три прохода.
> Состав `WINDOW_ANCHORED` тоже подтверждён.
>
> Не трогается: `src/lib/record/`, `openRecord.ts`, `tableRowOps.ts` — там идёт #189.

## Contract

1. Ни одна поверхность не предлагает шаблон дашборда — ни пустой холст, ни «+ Виджет», ни быстрое действие.
2. **Ни одна кнопка не остаётся видимой без эффекта.** Сохранённое `apply-template` исчезает с экрана
   в том же коммите, в котором исчезает механизм.
3. Хранилище, где оно лежит, открывается без ошибки и без потери остального: `qa-formula` работает,
   `widgets` / `table` / `fieldPresets` не трогаются.
4. **Шаблоны записи (`ProjectDefinition.templates`) не трогаются вообще** — решение пользователя.
5. Удалённый код уходит дословно в `docs/internal/archive/` — **не** в `src/archive`: его
   воскрешение уронило бы R0.4, где `ARCHIVE_PRESENT = false`.

## 1. Что происходит с сохранённым `apply-template` в хранилище

**«Оставить неработающую кнопку» недопустимо**, и «отключённая кнопка» — тот же дефект в вежливой
обёртке: она объясняет, что раньше что-то было, и не даёт ничего сделать.

**Решение: отбрасывать при чтении.** Один чистый фильтр в `migration.ts`, включённый в ту же цепочку,
где уже стоят `isLegacyTableConfig` / `migrateDashboardTransforms`:

```ts
export function dropTemplateQuickActions(config: DatabaseViewConfig): {
  config: DatabaseViewConfig; migrated: boolean;
}
```

Идемпотентен; возвращает исходную ссылку, когда ничего не нашёл (контракт `migrateAggregationCount`);
защищён `Array.isArray(config?.quickActions)` — ровно та проверка, которую кросс-модельное ревью
потребовало для `widgets`.

**Почему не фильтр в компоненте:** мусор остался бы в `data.json` навсегда, и следующий читатель типа
наткнулся бы на `kind`, которого нет в союзе. **Почему не принудительная перезапись всех видов:** она
трогает путь #145 с точкой восстановления ради одной кнопки. Запись всё же произойдёт — естественно,
через существующий `props.saveConfig(config)` при `migrated` в `dashboardView.ts`.

**Что видит пользователь `Безымянный проект / База данных`:** при первом открытии «Обзорный пресет»
исчезает, «Formula Builder» остаётся. Ряд не пустеет — визуальной дыры нет.

## 2. `ApplyTemplateQuickAction` уходит из союза

`QuickActionConfig` становится `= ToggleFormulaQuickAction`.

- **Давление невывода здесь хорошего сорта.** Единственный разбор по `kind` — `dashboardTemplates.ts:80-88`,
  он удаляется целиком; `DashboardCanvas.svelte:155-160` рисует `label`/`labelKey` без разбора. Значит
  TypeScript не заставит соврать нигде — он просто перестанет принимать литерал `kind: "apply-template"`,
  и **`migration.ts` не скомпилируется, пока из него не уберут генерацию артефакта.** Компилятор
  становится исполнителем пункта 3.
- **Цена** — там, где типизированный код встречает нетипизированный JSON: фильтр обязан читать сырую
  форму (`(a as { kind?: unknown }).kind !== "apply-template"`). Один локальный `as` над персистентными
  данными — не `@ts-ignore`, инвариант 1 не задет; тем же приёмом уже пользуется `isLegacyTableConfig`.
- **Прецедент `DataTableConfig.subBases` здесь НЕ применяется**, и это надо сказать в коммите: тот ключ
  носится нетронутым, потому что его удаление сделало бы данные немоделируемыми. Здесь артефакт — не
  пользовательские данные, а сгенерированная нашей же миграцией кнопка к нашему же механизму.

## 3. Что `migration.ts` выдаёт вместо двух действий

Одно — `qa-formula`. `toggle-formula-bar` живой (`DashboardCanvas.svelte:82` → `showFormulaBar`) и
единственная подсказка «здесь есть действия». Ключ `views.dashboard.quick.overview` уходит из четырёх
локалей. Новую кнопку не заводим: это функциональность внутри удаления, её никто не заказывал.

## 4. Что предлагает пустой холст

`WidgetGrid.svelte` теряет `{#each WIDGET_TEMPLATES}` (:70-75) и сохраняет «Добавить блок данных»
(:66-69). Тупика нет по двум проверенным фактам: кнопка ведёт в `widgetController.addWidget` — тот же
путь, что палитра; `DashboardBlockPalette` доступен, как только появился первый виджет.

Меняется **копия**: `views.dashboard.canvas.empty-hint` сегодня обещает «или выберите готовый шаблон» —
во всех четырёх локалях остаётся только про блок данных.

Продуктовый ответ: шаблон подставлял 3–6 виджетов, настроенных на **вымышленные поля**
(`overview-finance` собран вокруг финансовой схемы). В проекте без этих полей он давал холст, который
выглядит настроенным и ничего не показывает. Один блок над реальными полями честнее.

## 6. Тесты

**Главный, и тот, который забывают:** хранилище с устаревшим артефактом открывается.
Конфиг с `quickActions = [apply-template, toggle-formula-bar]` → `migrated === true`,
осталось одно действие, `widgets`/`table`/`fieldPresets` идентичны **по ссылке**. Плюс: `templateId`,
которого никогда не было в коде, тоже отбрасывается — фильтр по `kind`, а не по списку известных id,
иначе UNKNOWN из карты (какие id реально в хранилищах) остаётся дырой. Плюс идемпотентность: второй
прогон → `migrated === false` и та же ссылка. Плюс `quickActions: undefined` и не-массив не роняют.

**Что пиннит полноту удаления:** смонтированный `DashboardCanvas` с конфигом, несущим оба действия,
показывает **ровно одну** `.ppp-quick-action` — это единственный тест, доказывающий отсутствие кнопки
на экране, а не в объекте. Грep-ратчет не нужен: `tsc` не даст воскресить `kind: "apply-template"`.

**Baseline падает** (уходит `widgetTemplates.test.ts`). По прецеденту #160/#183 это называется вслух в
`CONTEXT.md`: тест, чей предмет удалён, — не покрытие.

## Risks — чего ворота не поймают

1. **Хранилище, которого мы не видели** — карта прямо пишет UNKNOWN. Смягчение: фильтр по `kind`, а не
   по списку id, плюс живой прогон на подтверждённом хранилище.
2. **Появится запись на диск там, где её не было.** Путь тот же (`saveConfig`), снимок #145 берётся
   выше — но это надо **увидеть**: открыть вид, закрыть, проверить `data.json` и что виджеты на месте.
3. **`readonly`-вид:** действия рисуются под `!readonly`, а миграция сработает и там. Проверить, что в
   readonly ничего не сохраняется вопреки ожиданию.
4. **Локали** — самая вероятная точка «забыли `uk`/`zh-CN`»; `svelte-check` этого не увидит.
5. **Бандл уменьшится.** В отличие от #178/#183 это runtime-код: байтовое равенство здесь не критерий,
   ожидаемый результат обратный — измерить дельту и записать.

## Rejected

1. Оставить кнопку неработающей или отключённой.
2. Оставить `ApplyTemplateQuickAction` «для совместимости» — прецедент `subBases` про немоделируемые
   данные; здесь данных нет.
3. Удалить только `getVerticalTemplates` — буква карты разошлась с решением пользователя.
4. Принудительная перезапись всех видов — дороже задачи, трогает путь #145.
5. Фильтровать в `DashboardCanvas` вместо миграции — мусор остаётся в `data.json` навсегда.
6. Оставить `TemplateConfirmDialog` «на будущее» — новый мёртвый файл в тикете про удаление мёртвого.
7. Заменить шаблоны «пресетами v2» — новая функциональность внутри удаления.
8. Пустой холст без единой кнопки — тупик для нового дашборда.
