## 4. Ручной прогон через Obsidian API (2026-08-28)

Плагин собран из рабочего дерева, задеплоен в `OBStests`, прогнан через Local REST API:
10 команд (11 минус удалённая `add-sub-base`), смоук демо A1–A7, roundtrip, и новый раздел
пайплайна 4a — миграция и точка восстановления M1–M5.

**Прогон нашёл два дефекта:**

1. Правило «одна копия на вид» в #145 теряло до-состояние второго события миграции. Обоснование
   правила оказалось ложным: payload берётся из памяти и всегда является до-состоянием именно
   этого события.
2. **Демо-генератор поставляет legacy-пайплайны** и мигрирует сам себя при первом открытии (#164).
   Первый файл восстановления в хранилище появился не от моего посева, а от штатного демо.

**Дважды прогон ложно «прошёл» из-за формы тестовых данных** (`kind` вместо `type`,
`config.transform` вместо `widget.transform`) — мигратор их молча игнорирует. Обе ловушки записаны
в пайплайн; вопрос о диагностике нераспознанного шага ушёл в #164.
