# Управление проектами 3.7.3: простой основной сценарий

[English](project-management-ux-3.7.3.md) · [Реализованная техническая основа](development-3.7.3-RU.md)

Статус: **реализация следующей итерации, 23.11.2026**. Владелец оценил тестирование кандидата 579c052d как относительно успешное по функциям, но отверг удобство управления. Это не приёмка 3.7.3 к выпуску. Стабильная версия — 3.7.2.

Первый этап в рабочей ветке: панель в общих настройках с поиском, открытием, передачей и архивом проектов; вход в ZIP-шаблон при первом запуске; групповой выбор папки или точного тега при упаковке; читаемое имя ZIP с датой и номером при совпадении. Окна переноса используют общую обработку видимой области при появлении клавиатуры и перенос длинного текста. Подтверждение этих изменений на настоящем iPhone ещё требуется. Единый мастер, автоматическое включение связанных файлов, упрощённая распаковка и миграция имён конфигураций остаются следующими этапами. Старые файлы автоматически не переименовываются.

## 1. Задача и основания

Человек должен сохранить, передать или открыть проект без знания палитры команд, хешей, JSON, привязок и промежуточных журналов. Общий стиль Obsidian и действующие настройки сохраняются. «Просто» означает меньше обязательных решений; защиты от потери данных остаются.

Подтверждено по исходникам кандидата: `src/ui/settings/settings.ts` даёт одну кнопку входа в управление копиями; `src/ui/settings/Projects.svelte` управляет командами, а не переносом проектов. Упаковка, проверка ZIP, привязки и области разнесены по отдельным окнам `src/ui/projectFiles`. `packageService.save` формирует имя ZIP из двух полных хешей. `Onboarding.svelte` предлагает демо и пустой проект, но не ZIP-шаблон.

По отчёту владельца: поля уходят под мобильную клавиатуру, текст выходит из родителей. Это обязательные дефекты для воспроизведения, а не пожелания. Текущие окна здесь не захвачены: Computer Use сообщает `native pipe unavailable`. Документ основан на отчёте и коде, не является визуальным аудитом или подтверждением исправления iPhone.

## 2. Панель в общих настройках

В начале настроек Projects Plus располагается раздел «Проекты». Тот же экран доступен из навигации самого плагина; команды остаются дополнительными быстрыми действиями.

| Область | Основные элементы |
| --- | --- |
| Начало | «Создать проект», «Открыть шаблон» |
| Проекты | Поиск, список активных проектов; архив отдельным раскрываемым разделом |
| Карточка проекта | Имя, папка/тег, понятный статус; «Открыть», «Поделиться», меню остальных действий |
| Меню проекта | «Создать копию», «Сохранить шаблон», «Восстановить», «Настроить», «Архивировать» |
| Копии | Выбранная папка, дата последней успешной копии, автокопирование и «Обновить сейчас» |
| Требует внимания | Прерванный перенос, конфликт внешней правки, не обновившаяся копия; действие для каждого случая |

Название, количество файлов и дата — на первом плане. ID, хеши, пути журнала и версии схем — только в раскрываемых подробностях. На телефоне действия переносятся в вертикальный список; таблица с горизонтальной прокруткой не используется. Настройка горячих команд переносится в дополнительные настройки без сброса сохранённых команд.

## 3. Состав пакета без пофайлового выбора

Мастер «Поделиться проектом» начинает с проекта и одного способа включения материалов:

| Выбор | Что собирается |
| --- | --- |
| «Все материалы проекта» | Файлы, входящие в проект; фильтр открытого вида не сокращает копию |
| «Из папки» | Выбранная папка; вложенные папки включены по умолчанию |
| «По тегу» | Подходящие заметки; включение вложенных тегов показано отдельно |
| «Связанные заметки и файлы» | Материалы проекта и локальные цели исходящих ссылок с защитой от циклов |
| «Только настройки» | Шаблон конфигурации без личных записей |

Вложения выбранных заметок включаются по умолчанию; эту опцию можно выключить. Обратные ссылки не расширяют состав автоматически. Для связанных заметок выполняется ограниченный обход исходящих ссылок; область и количество видны до подтверждения. Сеть и внешние URL не скачиваются. Из источников со сводными строками нельзя угадывать исходные файлы: мастер предлагает папку или тег.

Сначала строится список путей и размеров, затем показывается итог: «Ремонт квартиры · 24 заметки · 8 вложений · 3 МБ». Дерево состава можно раскрыть, снять отдельные элементы или добавить файл вручную. Это дополнительная возможность, а не обязательный путь. Переключение способа заменяет предыдущую область; скрытого объединения папок и тегов нет.

До кнопки «Создать архив» содержимое не копируется. Повторяющиеся файлы включаются один раз. Исключённые заметки проекта, скрытые настройки, служебные копии и готовые архивы не подхватываются обходом. Превышение лимита показывается с выбором меньшей области; тихое усечение запрещено. Смена файлов или настроек после просмотра требует нового подтверждения изменившегося состава.

## 4. Понятные файлы и папки

Примеры новых имён: `Ремонт квартиры — 2026-11-23.zip`, `Ремонт квартиры — шаблон.zip`, `Проект.json`, `Ремонт квартиры — 2026-11-23 14-30.md`. При совпадении предлагается `Ремонт квартиры — 2026-11-23 (2).zip`. Имя можно изменить до сохранения. Длинные имена проектов безопасно сокращаются для файла, но в интерфейсе имя проекта остаётся полным.

Хеш подтверждает содержимое внутри manifest/индекса, а не служит пользовательским именем. Владение файлом определяют ID и подтверждённый индекс. Имена одинаковых проектов, регистр, NFC, недопустимые символы и занятые родительские пути учитываются до записи и повторно возле неё. Совпадение имени никогда не разрешает перезапись.

Все новые видимые документы имеют понятные имена; служебная подготовка помещается в отдельно названную область с пояснением назначения. Старые экспортированные ZIP и пользовательские заметки автоматически не переименовываются. Старые копии продолжают читаться; переход имён — отдельное проверяемое действие с отчётом и возможностью возврата. Без обновления индекса и изоляции источников менять только имена файлов нельзя.

## 5. Импорт и выбор назначения

Основной путь: «Открыть шаблон» → выбрать ZIP → выбрать папку → «Добавить проект». Внутри мастера три экрана: «Шаблон», «Куда добавить», «Проверить и добавить». Подготовка, проверки и журнал выполняются за этими действиями, не требуют отдельных технических кнопок.

По умолчанию предлагается новая папка с именем проекта. Можно выбрать другую папку хранилища, изменить имя проекта и выбрать «С материалами» или «Только настройки». В выбранной папке находятся заметки и `Проект.json`. Конфликты решаются предложением новой папки или безопасных новых имён с согласованным обновлением ссылок; перезапись чужих файлов по умолчанию не предлагается.

Для проекта по тегам папка новых заметок всё равно обязательна и предлагается сразу. Пользователь отдельно видит, подключатся ли существующие заметки с таким тегом. Желаемый простой режим — «Только добавленные материалы»; он требует явного сохраняемого ограничения области источника, действующего и для будущих заметок в выбранной папке. Нельзя имитировать его однократной фильтрацией предпросмотра. Сохранение исходного широкого правила — отдельный осознанный выбор. DQL автоматически не переписывается; если правило нельзя безопасно ограничить, мастер объясняет это до установки.

Несколько проектов получают отдельные понятные подпапки и общий просмотр связей. Исходный ZIP сохраняется по умолчанию. Удаление в настроенную корзину доступно после подтверждённого успеха, не является обязательным решением. Итог: «Проект добавлен» с кнопкой «Открыть проект» и ссылкой на папку.

## 6. Ссылки и совместимость пакетов

Для новых пакетов нужен версионированный каталог точных целей ссылок отправителя: исходный файл, проверенная ревизия текста, позиция/исходный текст ссылки, разрешённая цель и её роль. Он строится по нативным метаданным и повторно проверенным байтам, а не по совпадению имени файла. Относительные ссылки, wiki, YAML, aliases, заголовки и блоки сохраняются.

Каталог вместе с неизменяемым планом размещения позволяет привязать включённые файлы автоматически. Показываются только исключения: отсутствующая цель, внешний файл, конфликт или неподдерживаемая конструкция. Их можно решать группой по папке, когда соответствие однозначно и явно подтверждено.

Текущая схема1 строго отвергает неизвестные поля, поэтому каталог нельзя незаметно дописать в неё. Проектируется схема2 с отдельной валидацией и сохранением чтения схемы1. Для старого ZIP без каталога неоднозначные wiki-ссылки остаются явным выбором; уникальное совпадение basename не доказывает намерение отправителя.

## 7. Первый запуск

Три равноправных понятных входа: «Создать проект», «Открыть шаблон», «Попробовать пример». Выбор ZIP открывает тот же мастер, что панель настроек. Назад/отмена возвращают к первому экрану без добавления пустого проекта и потери выбора. Предварительный просмотр шаблона не исполняет его запросы и формулы.

Выбор локального ZIP из хранилища обязателен. Получение ZIP из «Файлов»/внешнего приложения через системный выбор или открытие проверяется отдельным прототипом публичных возможностей каждого хоста. При отсутствии API даётся честный путь «Сначала сохранить ZIP в хранилище»; скрытый доступ к файловой системе не используется.

## 8. Клавиатура, текст и доступность

Все формы переноса, выбора папок и применения конфигураций используют один общий контейнер: заголовок, одна прокручиваемая область и доступные действия. Нельзя оставлять второе полноэкранное окно под picker или прибавлять два отступа клавиатуры. За основу берутся `visibleViewport`, `onKeyboardChange`, `fitVisibleViewport` и существующие токены; перенос их на native Modal проверяется, а не применяется слепо.

Границы вычисляются в ownerDocument/defaultView, с учётом visualViewport, safe area, панели Obsidian, клавиатуры и поворота. Фокусируемое поле и кнопки подтверждения доступны в видимой области. Обновление списка не сбрасывает ввод, caret, IME, фокус и прокрутку. Подсказки остаются в правильном слое. Крупный текст, длинное имя и непрерывная строка не расширяют родителя: min-width:0, переносы и вертикальные действия вместо обрезания важных подписей.

Проектный критерий для сенсорных действий — область не менее 44 CSS px; темы, текстовые подписи, видимый фокус, озвучиваемые статусы, reduced motion и клавиатурная навигация сохраняются. Состояния не передаются одним цветом. Это требования проекта, не заявление о сертификации доступности.

## 9. Операции, ошибки и внешние правки

Назад сохраняет выбор. Повторное открытие активного переноса показывает его состояние, не запускает второй экземпляр. Отмена во время записи объясняет, остановлено ли добавление или только закрыто окно. После перезапуска видны «Продолжить» и «Отменить перенос, сохранив файлы».

Показываются человеческие этапы и счётчик, когда он известен: «Собираем материалы», «Проверяем ссылки», «Добавляем 5 из 24 файлов». Успех основной записи и сбой обновления копии различаются: «Проект добавлен; копию настроек нужно обновить». Ошибка содержит следующее действие, техническая причина раскрывается отдельно. Закрытие/фон приложения не должны означать ложный успех.

В карточке проекта доступны «Применить изменения из файла» и «Восстановить копию» с понятным diff. JSON не требуется редактировать для обычного управления. Внешний черновик не перезаписывается автокопированием; прерванные подтверждения собственных записей остаются восстанавливаемыми.

## 10. Архитектура реализации

| Компонент | Ответственность |
| --- | --- |
| ProjectManagementPanel | Настройки/список/статусы; существующий store, без второго writer |
| TransferWizard | Один пошаговый экран для панели, навигации и onboarding; короткие подписи |
| SelectionPlanner | Режим области, native membership/metadata, дедупликация, ограничения, причины включения; без записи payload |
| TransferDraft | Неизменяемый снимок состава, ревизий и решений; устаревает при изменениях |
| SenderLinkCatalogue | Точные отправительские цели, байтовые проверки, ограниченный обход; схема2 |
| PackageNaming / Placement | Понятные имена, collision-safe создание, внутренние ID и индексы владения |
| OperationCoordinator | Один изменяющий перенос на vault, прогресс, поздние callbacks, восстановление |
| Shared transfer form | Общие границы/прокрутка/фокус, единый контракт мобильных форм |

Повторно используются проверенные package codec, path guards, типизированный remap, подтверждающий settings writer, quarantine, installer/journal/recovery и configuration service. Отображение и область выбора отделяются от права на запись. Чтение любого входящего ZIP остаётся недоверенным. Изменение имён требует версии индекса копий и обновления isProjectCopyPath/eligibility; служебные Markdown не должны попадать в folder/tag/native/DQL file-linked результаты. Глобальные DQL-агрегаты по-прежнему требуют явного исключения области копий.

Для ограничения тега папкой сначала проверяется существующий `native-query`: источник tag плюс каноническое условие пути через общий filterEvaluator, с сохранением ID источника. Прототип обязан доказать границу папки, вложенность, новые заметки, исключения и поведение лимита. Нельзя сохранять незнакомую опцию в обычный tag-source, которую прежний runtime проигнорирует и тем самым расширит область. Если существующий контракт не выражает точную область, требуется версионированное изменение модели, а не второй фильтрующий движок.

## 11. Порядок работ

1. Общий мобильный контейнер и воспроизводители клавиатуры/переполнения; одинаковые правила всех новых окон.
2. Панель управления и единый мастер; команды вызывают те же действия. Никаких переименований старых файлов на этом шаге.
3. SelectionPlanner и четыре массовых режима, просмотр состава, понятные имена новых ZIP.
4. Каталог ссылок/схема2, понятные конфигурации/снимки и проверяемый переход индекса; совместимость старых пакетов.
5. Импорт с назначением/областями, вход из onboarding, восстановление из панели и полный сквозной прогон.

Каждый шаг завершается проверкой соответствующей функции и независимым ревью изменений; полный C1 и новый кандидат — после связного сценария. Мобильные дефекты — блокер выпуска, не полировка после релиза.

## 12. Приёмка

- Новый пользователь без команд создаёт проект, упаковывает папку/тег, открывает шаблон и восстанавливает копию по одним текстовым кнопкам.
- Чистый самодостаточный пакет импортируется без пофайловой привязки; старый неоднозначный пакет получает понятные исключения без угадывания.
- Одинаковые имена, Unicode/NFC, вложенные теги, циклы ссылок, дубли, большие области, изменяющийся источник и конфликты назначения не приводят к потере или тихому пропуску файлов.
- Проверены iPhone 320/375/390 CSS px, увеличенный шрифт, длинные русские подписи, IME, клавиатура, поворот и вложенный выбор папки. Физический iPhone обязателен; эмуляция не заменяет приёмку.
- Прерывания до/после записи файла и основной публикации, повторные клики и восстановление после рестарта сохраняют прежние данные и корректный статус.
- Старые schema1/копии/счётчики/формулы/порядок проектов сохранены; переход именования обратим и проверен чтением результата.
- Финальный протокол отдельно отмечает автоматические результаты, ручные результаты и ограничения API системной передачи файлов.
